1) Изоляция АБС: Защита перегруженной АБС. Все взаимодействие должно быть асинхронным через брокер сообщений (Kafka). Это удовлетворяет NFR-1.
2) Вынос бизнес-логики: Критическая логика (управление ставками, обработка заявок) выносится из АБС и монолита интернет-банка в отдельные сервисы. Это позволяет развивать их независимо, масштабировать (NFR-6) и дает гибкость.
3) Обход ограничений подрядчика: Новый функционал (СМС-верификация) реализуется в новом сервисе, который интегрируется с монолитом интернет-банка через API. Это удовлетворяет NFR-5.
4) Единый источник истины: Создается отдельный Сервис ставок, который становится единственным местом, где хранятся и рассчитываются все ставки. Это решает проблему с Excel и обеспечивает консистентность данных.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

Альтернатива 1: Прямая интеграция Интернет-банка с АБС через API

Описание: Монолит интернет-банка вызывает API АБС напрямую для проверки ставок, создания заявок и открытия счетов.

Недостатки: Высокий риск нарушения работы АБС из-за нагрузки (нарушение NFR-1). Низкая отказоустойчивость — падение АБС приведет к падению процесса открытия депозитов. Сложность масштабирования.

Альтернатива 2: Разработка всего функционала внутри монолита АБС

Описание: Все новые процессы (ставки, заявки) реализуются как модули внутри АБС на PL/SQL и в Delphi-клиенте.

Недостатки: Увеличит нагрузку на и так перегруженную АБС. Крайне медленный цикл разработки и высокая сложность внесения изменений. Не решает проблему с производительностью UI (NFR-2). Не позволяет независимо масштабировать онлайн-каналы.

**Недостатки, ограничения, риски**

Подробно опишите здесь недостатки, ограничения и риски выбранного решения.

Сложность: Внедрение микросервисной архитектуры и Kafka увеличивает операционную сложность. Требует новых компетенций у команды.

Стоимость: Необходимы ресурсы на развертывание и поддержку новых инфраструктурных компонентов (Kafka, PostgreSQL).

Риск несогласованности данных: При асинхронной обработке возможны временные несоответствия данных, например, задержка между созданием заявки и ее появлением в АБС.

Ограничение: Требуется доработка монолита интернет-банка для интеграции с новыми сервисами через API, что может быть нетривиально.
